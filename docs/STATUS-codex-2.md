# Codex round 2 status — 2026-10-29

## Scope and execution boundary

Changes are confined to `src/Prism.Lighting`, new `src/Prism.Service`,
`tests/Prism.Lighting.Tests`, new `tests/Prism.Service.Tests`, `scripts/`,
`Prism.sln`, and this file. No App, Core, Hardware, or Router source files were
edited. `PipeContract` and its public wire shape are unchanged. No commit was made.

Only builds, unit tests, source inspection, reference browsing, and PowerShell
syntax parsing were performed. The service executable, real adapters, actual
named-pipe listener, DPAPI implementation, discovery, OpenRGB launcher, service
scripts, hardware, driver/service queries, registry, WMI methods, router, and lamp
were **not run or accessed**. Tests use fakes and in-memory streams. Temporary test
settings/token files live under the assigned test output directories and are removed.

## What exists

### Lamp transport

- `MiioProtocol`: fixed 32-byte hello, big-endian header/device/stamp parsing,
  AES-128-CBC/PKCS7, MD5-derived key/IV and packet checksum, length and checksum
  rejection. Pure byte operations, independent of sockets.
- `MiioLampClient`: connected UDP 54321 behind `IMiioTransport`, lazy hello,
  monotonically tracked device stamp without discarding fractional seconds on
  subsecond requests, JSON-RPC IDs and reply/device matching, null-terminated UTF-8
  payloads, two-second exchange deadlines, at most three attempts, cancellation,
  serialized commands at least 500 ms apart, and 500 ms smooth transitions.
  Implements power, brightness, RGB, CT, and the five-property `get_prop` request.
  There is no miIO music mode. Dispose clears the copied token.
- `LampFactory`: prefer configured TCP 55443 / SSDP-discovered Yeelight endpoints;
  fall back to miIO with a configured host and 16-byte token; otherwise report
  not configured. All network boundaries are injectable. Service retries failed
  lamp setup with backoff and reports its selected transport.
- `LampTokenStore`: `%APPDATA%\Prism\lamp.json`, DPAPI CurrentUser ciphertext,
  with an injectable protector. No token is put in settings or pipe state.
- `LampSync` allows up to two updates per second for miIO, preserving the existing
  Yeelight normal/music caps and color smoothing.

The fixed known packet test uses the published zero-token/device-id/epoch/plaintext
fixture in [python-miio 0.5.12 test_protocol.py](https://github.com/rytilahti/python-miio/blob/0.5.12/miio/tests/test_protocol.py)
(`build_msg` and `test_decode_json_payload`). Its expected packet hex was independently
materialized using PowerShell AES/MD5; it is not generated by Prism's codec during
the test. Encryption/checksum layout was also checked against
[python-miio's protocol implementation](https://github.com/rytilahti/python-miio/blob/master/miio/protocol.py).

### Service host and IPC

- New `net8.0-windows` Worker executable, registered in the solution with its tests.
  `--console` uses the console lifetime. `--mock` implies console, selects fake
  sensors/controls/RGB/lamp/router/health, and uses in-memory settings. Even adapter
  recovery paths remain fake in mock mode.
- `UseWindowsService()` uses a small local generic-host/`ServiceBase` SCM lifetime
  adapter (`WindowsServiceHosting.cs`). The additional Microsoft WindowsServices
  NuGet package was unavailable because package-network access is blocked here.
  The implementation waits for host shutdown before completing SCM stop and uses
  the existing cached ServiceController package. This host uses the installed
  `Microsoft.AspNetCore.App` framework for generic hosting; deployment therefore
  needs that .NET 8 runtime or a self-contained publish. SCM integration was not run.
- `LhmHardwareMonitor` snapshots at 1 Hz configure/apply the existing `FanController`.
  `EffectEngine` renders to the RGB backend at 30 fps; lamp sync runs independently
  so lamp/network latency does not stall fan polling or RGB frames.
- OpenRGB defaults to `127.0.0.1:6742`, selects direct mode, reconnects after failure,
  and reports connectivity. Persisted sync IDs derive from controller metadata,
  with an occurrence suffix for otherwise identical controllers. `OpenRgbProcess`
  can start a configured bundled `OpenRGB.exe --server --noautoconnect`, hidden,
  only when `LaunchOpenRgb` is explicitly enabled. No process was launched.
- One shared RouterClient/session with read-only signal polling nominally every
  two seconds, bounded ping history via PingMonitor operations, and single-flight
  SpeedTest execution on command. Router credentials/session reuse the unmodified
  Router module. Real router polling is enabled with `RouterEnabled` in settings.
- Multiple pipe clients, UTF-8 JSON lines on `prism`, hello/version/client validation,
  correlated responses, subscribe and approximately 1 Hz state pushes, every
  contract command, serialized settings mutation, bounded request lines and pending
  work, cancellation, and write deadlines. A slow speed test does not hold the
  settings gate or prevent another command on the same connection.
- `startSpeedTest` answers once upon completion with the existing `Response.Data`
  slot containing `{ ping, jitter, down, up, at }` from `SpeedTestResult`; clients
  should allow time for the test and correlate replies by ID. State pushes continue.
  No shared contract additions were needed.
- Pipe DACL permits local INTERACTIVE read/write and SYSTEM/Administrators full
  access, explicitly denies NETWORK, and disables inherited access rules. Tests
  inspect only the in-memory ACL; no real pipe was created.
- State projection keeps missing sensor values null, including fan RPM/percentage,
  and distinguishes a real zero. Covers CPU/core/GPU/RAM/DIMM/board/disk/network,
  fan configuration, RGB devices, lamp, router, and service health.

### Settings, scenes, health, and stop safety

- Validated JSON settings at `%ProgramData%\Prism\settings.json`, atomic file
  replacement, fan modes/custom curves/sources per writable group, lighting,
  device sync, lamp, scenes, router enablement/host, and optional OpenRGB path.
  Pump requests are rejected. Invalid commands and failed persistence leave the
  current desired settings unchanged. Once saved, client disconnection cannot
  prevent publication to the runtime. Runtime reconcilers apply desired settings.
- Scene values follow `docs/design/Scenes.dc.html`: Gaming = Turbo, Smart, orange
  lamp 60%; Work = Standard, static `#E4E4E7`, warm lamp 90%; Night = Silent,
  dim indigo Breathing, lamp off; Movie = Silent, Adaptive, lamp follows average.
  Values unspecified by the design are explicit defaults: Work CT 3500 K, Night
  lighting 15%/speed 0.5, Movie lighting 40%, and 60% Movie lamp brightness.
- Read-only health probe reports ASUS fan/AURA/iCUE/Corsair conflicts, missing
  PawnIO, and lack of elevation. PawnIO is checked as a named driver service,
  rather than assuming the Win32 service enumeration includes drivers. Runtime
  warnings cover OpenRGB failure, lamp setup/failure, router single-login conflict,
  sensor failures, and unavailable capture inputs.
- BIOS restoration is wired through worker stop/fault, runtime cancellation,
  disposal, Ctrl+C, process exit, and AppDomain unhandled exceptions. Worker faults
  set a nonzero exit code for recovery. Existing fan safety/pump enforcement is
  reused. Cleanup cannot be guaranteed after hard kill, native process failure,
  OS hang, or power loss.
- Install/uninstall PowerShell scripts include ShouldProcess/WhatIf support,
  quoted executable paths, delayed auto start, restart recovery and exit-code
  checks. Installation does not start the service. Scripts were syntax-parsed only.

## Open questions and integration limits

- No real hardware, lamp firmware, OpenRGB server, SCM lifecycle/recovery, pipe ACL
  access from a separate user, router, or service account provisioning was tested.
- CurrentUser DPAPI is identity-specific. The desktop user's `%APPDATA%` secrets
  cannot simply be consumed by LocalSystem. Provision lamp and Router credential
  stores under the chosen service identity before enabling real integrations;
  no secret-import/provisioning pipe command is present in the frozen contract.
- Audio and screen capture were not supplied by round 1; Music/Adaptive retain
  fallback inputs and publish a warning in real mode. Smart receives live CPU
  temperature. Movie's actual screen-follow behavior needs a capture provider.
- OpenRGB controller identity is metadata-based; indistinguishable devices without
  serial/location still depend on occurrence order. Native controller type is
  currently exposed as its numeric string in `RgbDeviceState.Kind`.
- Reported lamp settings are the last acknowledged desired settings, not continuous
  telemetry from external Mi Home changes. The miIO `get_prop` API is available,
  but external change reconciliation is not yet scheduled by the host.
- State readings depend on LHM naming and exposed sensors. In particular CPU/GPU
  model variants or multiple storage/network devices may need mapping refinements
  after explicitly authorized integration testing; missing data remains null.
- Settings/token provisioning currently uses files/library APIs. The contract has
  no commands to configure endpoints, OpenRGB executable paths, or secrets.
- No automatic scene triggers or service/driver conflict resolution are performed;
  scenes are applied by the existing command and conflicts are reported.
- OpenCode's App work was still in progress and absent from the solution during
  this validation. Its files were not modified or used to claim UI integration.
